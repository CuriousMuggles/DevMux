# 文档索引与引用链

一个主题只允许有一个权威文档；其余位置只能链接过去，不能复述。改文档前先看这张表，确认改的是权威源还是引用点。

## 随包文档（`doc_links.DOCUMENTS`，会进 ZIP 和 `dist/`）

| 文档 | 读者 | 唯一权威的内容 | 引用了谁 |
|---|---|---|---|
| `README.md` | 首次接触的人 | 项目定位、能力一览、下载与启动、构建入口 | 使用说明、串口说明、Agent 接入说明、插件开发说明、发布说明、第三方许可 |
| `使用说明.md` | 使用者 | 安装、接入目标、终端与布局、文件传输、跨机中转（步骤+状态+权限+接管）、串口与 PowerShell 的界面操作、继电器与 DB、诊断与清理、插件安装、常见问题、数据与升级 | README 不回指；指向串口说明、Agent 接入说明 |
| `docs/使用说明/串口使用说明.md` | 使用者、Agent 接入方 | 串口参数、输入权与代次、日志格式、快捷指令存储、XMODEM 全流程、serial 扩展接口 | 使用说明（第六章） |
| `Agent接入说明.md` | Agent 接入方 | MCP/CLI 注册、工具表、认证与限额、扩展调用、任务恢复边界 | 使用说明、串口说明 |
| `docs/插件开发说明.md` | 插件开发者 | 工程结构、前端/后端 SDK、权限声明、打包、插件发布规范 | 无（自成体系） |
| `发布说明.md` | 使用者、升级前必读 | 每个版本的实际变化与升级要求 | 无 |
| `LICENSE`、`第三方许可.md` | 分发者 | 授权与第三方组件清单 | 无 |
| `vendor/usb-relay/来源记录.md` | 分发者、合规核对 | 继电器 DLL 的上游来源与摘要记录 | `第三方许可.md` |

随包文档的硬约束：**所有相对链接必须落在上面这张表里**（`doc_links.check_closed_set` 校验），否则解压后的 ZIP 会出现死链。

## 规则

1. **一主题一权威源**：改行为先改权威文档，再改引用点的措辞。不允许两处各写一套步骤。
2. **新增随包文档**：同时加进 `doc_links.DOCUMENTS`、本表、`README.md` 的文档表；跑 `tests/test_docs_version.py`。
3. **新增内部文档**：放 `docs/internal/`，在本表登记，不从随包文档里链接（可用纯文本提及路径）。
4. **改文件名或位置**：全仓搜索旧名，`py doc_links.py` 必须零问题。
5. **版本变化**只写 `发布说明.md`；使用说明里出现版本化小节会被测试判失败。
6. **文件名用中文**：「对象+文档类型」两段式，如 `串口使用说明.md`、`跨机中转设计.md`、`来源记录.md`。中文名对 ZIP、`docs/`、`git` 均已验证可用，`tests/test_docs_version.py` 会拦住新出现的英文名文档。例外只有四个：`README.md`（GitHub 仓库首页约定）、`LICENSE`（授权文件惯例）、`AGENTS.md`（Agent 工具约定）、`vendor/usb-relay/source/README.md`（上游原文件，不改动）。
