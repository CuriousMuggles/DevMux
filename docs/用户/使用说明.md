# DevMux v3.2.2 使用说明

DevMux 是一个 Windows 调试工作台：把 ADB 终端、串口、PowerShell、文件传输、跨机中转和硬件工具收在同一个窗口里。设备接在本机就直接操作；接在另一台电脑上，配一次主从关系也能在本机操作；需要继电器或 DB 烧写时按需装插件。

**三步开始用**

1. 解压并运行 `DevMux.exe`（Windows 10 1809 或更高，需 WebView2 Runtime）。
2. 接上要用的目标，按你手上的设备选一项或几项：
   - **Android 设备**：USB 连接，在设备上允许 USB 调试，随后出现在设备栏。
   - **串口设备**：接好适配器并记住 COM 号，从「窗口 → Serial（串口）…」打开。
   - **另一台电脑上的设备**：两端配好同一共享目录并确认连接，远端设备出现在设备栏。
   - **继电器、DB 烧写**：到「工具 → 插件管理」装对应 `.dmp` 并启用。
3. 在设备栏或对应窗口选中目标开始操作：终端出现回显、串口收到输出、面板能查到设备，就说明已经接通。

阅读顺序：第一至五章是主线（装好、终端与布局、传文件、跨机中转），第六至九章接硬件时按需查阅，第十至十二章是维护、排错与进阶。人工使用发布版不需要安装 Python，也不需要读源码。

## 一、功能总览

核心三项：**多设备、多终端的工作区**、**文件上传下载**、**跨机中转**。终端包括 ADB、PowerShell 和串口三类；诊断日志是内置的辅助工具，直接可用。

**继电器、DB 固化烧写、米家、eBPF 由插件提供**：四个官方 `.dmp` 随包放在 `plugin/`，安装并启用后才出现在工具菜单，没装的插件没有入口。安装见第十一章，继电器和 DB 的用法见第八、九章。

| 想完成的事 | 软件提供的功能 | 从哪里进入 |
|---|---|---|
| 同时查看和操作多台设备与终端 | 自动发现 Android 设备，每台设备一个终端；PowerShell、串口窗口共用同一工作区 | 主界面设备栏和终端区 |
| 调整多个终端的显示方式 | 网格、水平、垂直、单屏，最小化/最大化、拖出独立窗口 | 终端区布局按钮、窗口标题栏 |
| 减少重复输入、保存调试信息 | 快捷命令、查找、录制、设备文件编辑 | 终端工具栏；「文件 → 查找」 |
| 在电脑和设备间传文件 | 文件/文件夹上传，多个设备文件下载；支持远程设备 | 设备终端的 ↑ / ↓ |
| 操作接在另一台电脑上的设备 | 共享目录中转，主控连接从机后统一显示设备 | 「工具 → 跨机中转配置…」 |
| 在本机或从机运行电脑命令 | PowerShell 终端 | 「窗口 → PowerShell…」 |
| 与串口设备通信 | COM 枚举、参数设置、文本或 HEX 收发、XMODEM 双向传文件 | 「窗口 → Serial（串口）…」 |
| 控制 USB 继电器 | 查找设备、逐路/全部接通或断开 | 装 `usb-relay` 插件 →「工具 → USB 继电器…」 |
| 烧写 DB 固化包 | 识别镜像、预览计划、执行及查看进度 | 装 `db-flash` 插件 →「工具 → DB 固化烧写…」 |
| 查看米家设备、调试 eBPF | 扫码登录米家账户；在设备上做 eBPF 调试（以插件界面为准） | 装 `mijia` / `ebpf` 插件 → 工具菜单 |
| 排查连接异常、查看运行记录 | 只读 ADB 诊断、日志查看、闲置缓存清理 | 「⚕ ADB 诊断」、「日志」、中转配置 |
| 让 Agent 操作上述能力 | MCP 或 JSON CLI 接入，查询目标、执行任务、收发文件及调用扩展 | 本文第十二章 |

本软件不提供手机屏幕镜像或触摸控制。

## 二、第一次使用

### 1. 准备电脑与程序

从 [官方 Releases](https://github.com/CuriousMuggles/DevMux/releases) 下载 Windows ZIP 和 SHA256SUMS.txt，核对 `Get-FileHash` 的 SHA-256。源码归档供开发者使用，不含 EXE。

1. 使用 Windows 10 1809 或更高版本，安装 WebView2 Runtime 和设备所需的 USB/串口驱动。
2. 完整解压到有写入权限的固定目录，例如 `D:\DevMux`，双击 `DevMux.exe`。发布版内置 Python 运行时及 ADB/fastboot，无需另外安装。
3. ZIP 应含 `DevMux.exe`、`plugin/` 下四个官方包、README.md、本说明、开发者说明、发布说明和构建证据。
4. 打开「工具 → 插件管理」，点「＋ 安装插件」选择 `plugin/` 中所需的 `.dmp`（可多选），装完在卡片上点「启用」；工具菜单随即出现该插件入口。
5. 程序会在 EXE 旁生成配置和日志。升级时先退出程序并备份该目录；替换 EXE 时保留原有配置、配对记录、快捷命令和其他用户资料。

### 2. 接上要用的目标

**Android 设备**

1. 在设备上开启 USB 调试，用支持数据传输的 USB 线连接电脑。
2. 设备弹出 USB 调试授权时，确认允许这台电脑调试。
3. 等待程序发现设备。设备栏出现设备标签，对应终端显示设备命令提示符后即可输入。
4. 可先输入只读命令 `pwd` 并回车，看到当前目录即说明终端能够收发。

**串口设备**

1. 接好适配器并安装驱动，在 Windows 设备管理器确认实际 COM 号。
2. 打开「窗口 → Serial（串口）…」，端口选实际 COM，按板卡文档填写波特率和帧参数。
3. 点「打开终端」，出现该 COM 的终端并看到设备输出，即可收发。参数细节见第六章。

**另一台电脑上的设备**

1. 两台电脑都运行程序，并且都能读写同一个共享目录；推荐填网络路径。
2. 插设备的那台设为“从机”，填共享目录并保存；你操作的那台设为“主控端”，填同一目录。
3. 主控从「连接对端」选择从机 →「确认连接」，显示“通讯已验证”后，远端设备出现在设备栏。完整步骤见第五章。

**继电器与 DB 烧写**

这两项以插件形式提供，先按第十一章装好并启用，再按第八、九章使用。

这些目标彼此独立：只操作接在本机的 Android 设备，就不必管串口和跨机中转。没有发现设备，先按第十三章排查。

### 3. 认识主界面

- **设备栏/终端标签**：选择要看的设备或窗口；多个设备同时在线时，先核对目标再输入。
- **终端区**：输入命令并看回显；网格适合同时观察多台，单屏适合专注操作一台。
- **窗口菜单**：打开电脑 PowerShell 或串口。
- **工具菜单**：配置跨机连接、管理插件；已启用插件的入口（如 USB 继电器、DB 固化烧写）也在这里。
- **设置/日志**：调整显示，查看程序运行信息。

## 三、终端与布局

ADB、PowerShell、串口三类终端共用同一套标签、布局和独立窗口；下面这些操作对三者都适用。

### 1. 输入、布局与独立窗口

1. 点击目标终端后输入，回车执行；`Ctrl+C` 通常可中断当前前台命令。
2. 使用网格、水平、垂直、单屏按钮切换排列；布局乱了可点「恢复布局」。
3. 拖动终端标题栏可移到独立桌面窗口，放到另一屏幕；点 ↙ 返回主终端区，原会话保留。
4. 最小化后点击标签恢复。手动关闭的终端不会被后台刷新自动弹回；需要恢复时点击主界面设备栏的 ↻ 刷新按钮。
5. 粘贴多行命令时程序会限速发送，等待完成后再继续操作。

ADB 终端是在 Android 设备上执行；PowerShell 是在所选 Windows 电脑上执行；串口是向指定 COM 口发数据。这三个窗口的操作对象不同。

### 2. 查找、录制与快捷命令

- **查找：** 点击要查找的终端，再使用「文件 → 查找」或 `Ctrl+F`，只搜索当前终端缓冲。
- **录制：** 需要留证时在目标终端开启录制，结束后停止并保存；输出按行带时间戳。
- **快捷命令：** 用于保存常用指令，点击即按当前窗口的设置发送。ADB 和串口各有一套指令集，都保存在程序旁 `devmux-data/commands.json` 中。
- **设备文件编辑：** 保存后会写回设备，保存前核对路径。

### 3. 命令框列编辑

1. 拖动命令框上沿，展开多行输入区；长行通过水平滚动查看。
2. 按住 **Alt**，用鼠标左键拖动框出多行中的同一列；垂直拖动可建立多个插入光标。
3. 松开后可直接输入、使用 Backspace/Delete，或用 Ctrl+C/X/V 复制、剪切和粘贴。单行粘贴重复到每个选中行；多行依次对应选中行，不足的行用空串替换，多出的行忽略。短行止于行尾，不自动补空格；删除不合并行。
4. Ctrl+Z 撤销，Ctrl+Y 或 Ctrl+Shift+Z 重做；Esc 或普通点击退出列选择。Enter 仍发送整个命令框，Ctrl/Shift+Enter 仍换行。

ADB、PowerShell 和串口的命令框以及独立窗口使用相同操作；终端输出区保持原有行为。

## 四、文件上传与下载

**电脑 → 设备：** 点击目标设备的 ↑ → 用 📁 选择文件或整个文件夹 → 用 🔍 选择设备目标目录 → 核对来源和目标 → 执行上传。目录会递归上传，选中的 `.sh` 文件会添加可执行权限。

**设备 → 电脑：** 点击 ↓ → 用 🔍 选择设备文件，可连续多选 → 选择电脑保存目录 → 执行下载。多选框中以 `；` 展示多个完整路径，手动改写会回到单路径模式。

远程设备使用相同入口。此时“电脑上的来源/保存位置”仍是主控电脑，设备路径属于选中的从机设备。先等传输完成，再核对文件名、大小；需要确认二进制一致时比较哈希。失败可能已留下部分文件，先检查实际目录再决定下一步。链接、特殊文件及 Windows 无法表示的文件名会被拒绝，应先在设备端整理成普通文件和目录。

## 五、跨机中转：操作另一台电脑上的设备

这里的“主控”是你坐着操作的电脑；“从机”是实际连接 USB 设备、串口或工具的电脑。两台电脑都要运行程序，并能读写同一个共享文件夹。

例如：设备接在实验室电脑 B，你在办公电脑 A 操作；A 设为主控，B 设为从机。两端可使用不同的映射盘符，但必须指向同一份共享目录；推荐填写清楚的网络路径，例如 `\\文件服务器\共享目录\adb-relay`。

### 1. 在从机 B 上设置

1. 打开「工具 → 跨机中转配置…」。
2. 启用中转，角色选择“从机”，填写共享目录；选择部署标识，没有时通过「新增…」创建。
3. 在高级设置中按需要设置“对外共享设备”、命令白名单和 shell 权限。上传需允许 `push`，下载需允许 `pull`。
4. 点击「保存并生效」，保持程序运行。从机等待主控连接，无需选择或确认主控。

### 2. 在主控 A 上设置

1. 打开同一配置窗口，启用中转，角色选择“主控端”。
2. 填写指向同一位置的共享目录，并选择部署标识。通常两端选同一部署最容易辨认；不同部署也可连接，仍需确认。
3. 点击「保存并生效」，从“连接对端”选择 B，核对电脑名和部署，点击「确认连接」。
4. 等待显示“通讯已验证”。B 上共享的设备随后会出现在 A 的设备栏中；操作方法与本机设备相同。

**看到电脑名字只表示已发现，看到“通讯已验证”才表示连接往返成功。** 如果已经验证却没有设备，到 B 上检查设备授权、驱动及共享设备范围。

| 界面状态 | 含义 | 下一步 |
|---|---|---|
| 从机等待主控 | B 已配置，还没接到有效连接 | B 保持运行，A 选择并确认 |
| 主控待确认 | A 已发现 B，尚未同意连接 | 核对电脑名与部署后点「确认连接」 |
| 正在验证 | 已确认，等待 B 的准入回执 | 等自动完成，失败按原因处理 |
| 通讯已验证 | 连接往返成功 | A 操作设备；没有设备就等 B 接入 |
| 对端离线 | 心跳中断，确认关系保留 | 启动对端或检查共享目录 |
| 连接已解除 | 原确认已撤销 | A 重新确认连接 |

一个共享目录（含部署标识）算一个“根”：根内可以连多台从机，换了根要重新确认。升级到含根隔离的版本后，旧配对需要 A 重新确认一次，此后同根重启会自动验证。

### 3. 部署要求与各工具权限

**两端使用同一版本。** 中转的执行与判定都在实际插着设备的那台电脑上完成，所以从机也要安装当前版本，只升级主控不够。

**两端系统时间尽量保持一致。** 时间偏差会影响日志、录制的时间戳和文件时间，也可能影响其他按时间判断的软件。在偏差较大的那台电脑上用管理员命令行执行 `w32tm /resync /force`（时间服务未启动先执行 `net start w32time`），或打开「设置 → 时间和语言 → 日期和时间 → 立即同步」。对时后不用重启程序。本程序只读取系统时间，不会替你修改系统时间。

**远程工具权限一律在从机上开。** PowerShell、串口、继电器、DB 烧写的权限互相独立，各自都要在 B 的对应面板把目标选为“本机”并勾选那行权限（继电器和 DB 还需在 B 的插件管理里勾「允许主控使用」）；A 不能替 B 打开权限。连接已确认不代表这些权限已开启。

```text
主控 A：选择目标 B，查看配置、发起操作
                 │ 已确认的共享目录中转
                 ▼
从机 B：本机开启对应权限 → 保存 B 的工具路径 → 驱动 B 的 USB/COM 设备
```

各工具面板顶部的配置位置示意（示例字段，不是真实截图）：

```text
目标电脑  [本机 / 已连接的从机 B ▼]  [刷新连接]
执行位置  所选电脑；切换目标后，下面的配置也随之切换
权限      [✓] 允许主控使用本机工具（自动启用插件）
工具配置  目录、COM 口、镜像和驱动均属于所选电脑
工具操作  先读取/检测，再按确认的目标执行
```

权限行只在目标选“本机”时出现；选从机时该行隐藏，改由从机自己勾选。

| 要配置什么 | 应在哪台电脑准备 | 完成后应看到什么 |
|---|---|---|
| 远程连接 | A、B 都运行程序并配置同一共享目录，A 确认 B | “通讯已验证” |
| 工具远程权限 | 到 B 的对应工具面板把目标选为“本机”，勾选权限行；继电器和 DB 还可在 B 的插件管理里勾「允许主控使用（自动启用）」 | 回到 A 选择 B 后显示可用；A 不能代开 B 的权限 |
| 固化包/镜像 | 放在实际执行电脑 B 上，填写 B 运行账户可访问的路径 | 目录确认成功，能够列出镜像 |
| USB/串口驱动和设备 | 装在实际插着设备的电脑 B 上 | 系统识别 USB/COM；面板枚举到目标 |

只在本机操作无需开启“允许主控远程使用”。路径例 `D:\DBPackage` 填写在目标 B 的烧写面板中，就指 B 的 D 盘，不会自动复制 A 的同名目录。网络路径需要 B 运行程序的账户可访问，A 的映射盘符不一定在 B 存在。

角色属于程序实例，同一台电脑可多开不同实例；操作前核对当前窗口使用的实例和目标电脑。

### 4. 接管与断开

设备终端共用同一条 shell，会看到相同的工作目录、运行程序和输出。A 操作远端设备时，B 的同一设备窗口同步显示相同输出（只做显示，不会重复执行）；同一时刻只允许一方输入。B「接管」后 A 只读，B「交还主机」后 A 重新获得输入；B 持权时 A 也可以在标题栏点「接管」取回。接管不等于停止当前程序，输入前先看正在运行什么。

主控点击「解除连接」可断开关系；下次使用需要重新确认。从机可停用中转停止共享。已经确认且未解除的关系会在下次启动时尝试恢复。断线后设备可能暂时保留为灰色，不能把保留的标签当作仍在线。

## 六、串口：与 COM 设备通信

### 1. 打开串口

**准备：** 将串口适配器接在执行电脑上，安装对应驱动；在 Windows 设备管理器确认实际 COM 号。设备管理器没有 COM 时先处理驱动和连接，软件不能凭空创建端口。

1. 本机使用：打开「窗口 → Serial（串口）…」，目标选“本机”，刷新 COM 列表并选择实际端口。
2. 远程使用：先到从机 B 的同一面板把目标选为“本机”，勾选顶部的权限行「允许主控使用本机工具」；回 A 选择 B，再刷新 B 的 COM 列表。
3. 按设备说明填写以下参数，再点「打开终端」。默认值只是初始配置，不代表所有设备的要求。

| 字段 | 初始值/示例 | 如何选择 |
|---|---|---|
| 端口 | `COM3`（示例） | 使用执行电脑实际枚举到的端口；拔插后可能变化 |
| 波特率 | `921600` | 以板卡文档为准，常用值可在下拉列表选择，也可手动填写 1～12000000 的整数 |
| 数据位 / 校验 / 停止位 | `8 / N / 1` | 对应常说的 8N1；其他组合需两端一致 |
| 流控 | 无 | 仅在设备和接线要求时选择 RTS/CTS、XON/XOFF 或 DSR/DTR |
| DTR / RTS 初始状态 | 关闭 | 界面不单独提供开关；在线应用其他参数时保留当前信号状态 |
| 文本编码 / 换行 | 按设备要求 | UTF-8/GBK/ASCII/Latin-1；CR、LF、CRLF、无 |
| 文本 / HEX | 文本或字节对 | HEX 示例 `41 0D 0A`，不自动追加换行 |

```text
Serial 配置示意
目标电脑 [从机 B ▼]   端口 [COM3 ▼]
波特率 [115200]      数据位 [8]  校验 [N]  停止位 [1]
流控 [无]
                     [打开终端]
```

打开成功应出现对应 COM 的终端和连接状态。先观察启动输出；需要发送时按设备要求选择文本/HEX、编码和换行。没有输出先核对接线、端口及设备是否真的有数据；乱码通常要核对波特率、编码和帧参数。

打开后默认进入主终端区，与 PowerShell、ADB 终端共用标签、网格/水平和单屏布局；拖动标题栏可移出为独立窗口，↙ 返回并保留会话。手动关闭的窗口不会被后台广播重新打开，需要时用主界面刷新按钮恢复。

远程串口：先在从机的 Serial 面板把目标选为“本机”，勾选顶部权限行「允许主控使用本机工具（自动启用插件）」。该权限独立于 PowerShell、继电器和 DB，主控不能替从机开启。权限撤销、解除配对、连接代次更新或节点停止会释放相关的远程接入，本机接入保留。

同一 COM 参数相同可共用输出，参数不同时必须先关闭原连接。输入权独占且 GUI 优先：任一 GUI 打开、接管或发送都会收回 Agent 的输入权，Agent 不能抢占 GUI 或另一个 Agent；GUI 点「交还输入权」后，Agent 也需要申请新的输入代次，此前排队的旧输入仍会被拒绝。另一个 GUI 持权时，先到那个窗口交还。关闭窗口只释放自己的接入，最后一个接入关闭后才释放物理 COM。

发送结果暂时未确认时，窗口继续显示收到的输出并暂停新输入，不重发；收到明确回执后恢复。长时间未确认可关闭窗口重开，先确认设备实际状态，再决定是否重新输入。端口被其他软件独占时需由使用者结束占用，本程序不会强行释放别人的进程。

不用时关闭自己的窗口；拔插后手动重开，不自动连接或重发。

### 2. 工具栏与设置

工具栏图标依次为：⇄ XMODEM 文件传输、📋 日志、⚡ 快捷指令、⌨ 输入权、⚙ 设置。⇄ 打开独立的 XMODEM 小窗。输入权按钮横排显示文字：GUI 持权时显示绿色“交还”，否则显示蓝色“接管”，点击即执行。

点齿轮打开独立设置小窗，可调整文本/HEX、编码、换行、字符间隔和本地回显；连接参数提供可选的波特率控件（也可直接输入）、5～8 数据位、N/E/O/M/S 校验、1/1.5/2 停止位和流控下拉。

改完参数点“应用串口参数”，当前选择立即应用到已打开的 COM，无需重开终端；“恢复当前值”放弃草稿。应用需要 GUI 持有输入权、无其他共用接入且无 XMODEM 任务；驱动拒绝时恢复旧参数，恢复失败则关闭 COM 并报错。换 COM 端口仍要关闭后重开；关闭设置或传输小窗不会关闭 COM。

### 3. 发送与显示

**命令输入：** Enter 发送，Ctrl+Enter 或 Shift+Enter 在当前光标/选区插入换行；↑/↓ 查当前窗口最近 50 条，相邻重复去重。多行粘贴和快捷指令会把内部 CR/LF/CRLF 转为当前所选换行，末尾已有换行不重复追加；选“无”则移除逻辑换行。HEX 按字节发送，不追加换行。历史只保留在当前窗口。

**本地回显：** 勾选后字符按下即显示，不等中转回执。若这次输入最终没送达，终端另起一行标出 `[输入未送达]`。设备自身也回显时不要勾选，否则同一字符出现两次。

### 4. 日志、快捷指令与 XMODEM

**日志：** 点 📋 选当前 GUI 电脑上的文件，“记录”开始、“停止”结束；已有文件从末尾追加，默认逐行时间戳。本机与远程串口的输出都存到这台电脑，不录入 XMODEM 协议字节；关闭串口时回收日志。

**快捷指令：** 点 ⚡ 切换、新增、编辑或删除指令集和指令，点击按当前窗口的文本/HEX、编码和换行发送。指令保存在程序旁 `devmux-data/commands.json` 的串口小节，与 ADB 指令集共用同一个文件但互不影响；旧版独立文件 `serial-commands.json` 会在首次启动时并入并改名 `.migrated`。本机与远程串口窗口共用这套指令集，保存失败会显示原因。

**XMODEM：** 点 ⇄ 打开独立小窗，按以下顺序操作：

1. 确认所选电脑与 COM 正确。参数需为 8 数据位并禁用 XON/XOFF；沿用当前波特率、校验、停止位、硬件流控和 DTR/RTS，程序不修改设备，也不执行烧写命令。
2. **发送**：先在设备端进入 XMODEM 接收模式，选择 128 字节或 1K 包长，再点「发送文件…」选本机文件。128 字节包按对端 C/NAK 自动使用 CRC16 或 checksum；1K 要求对端请求 CRC。单文件最多 64MiB，原文件不修改。
3. **接收**：先选 CRC16 或 Checksum，点「接收文件」，再让设备进入 XMODEM 发送模式。128 与 1K 包都能接收，界面显示实际接收字节与重试次数。成功接收后点「保存接收文件」，不覆盖已有文件；取消保存后可再次保存。
4. 远程串口的协议和临时文件在从机执行，最终文件保存在操作者本机。观察准备、等待握手、传输、结束确认和成功/失败；可「取消传输」，取消不能撤回设备已收到的数据。准备与传输期间普通输入、快捷指令和接管暂停，其他 GUI 或 Agent 也不能抢占。
5. XMODEM 不携带文件名和精确原始长度：发送尾块以 1A 填充，接收保留填充字节，二进制文件请按已知长度或摘要核对，不能简单删除所有尾部 1A。回执未知时点「查询 / 恢复准备」，沿用原任务，不重新启动文件。

原生独立窗口里点选择/保存文件会先返回主窗口，按提示再点一次；快捷指令的列表、编辑和指令集管理都在当前独立窗口内完成。未升级的从机没有 XMODEM 能力，按钮保持禁用。

以上是串口操作的完整说明。端口参数、输入权代次、日志格式与 XMODEM 回执的内部规则，以及 Agent 调用串口的动作与参数，见 [开发者说明](/docs/用户/开发者说明.md)。

## 七、PowerShell：在电脑上运行命令

1. 打开「窗口 → PowerShell…」，选择本机或已连接从机。
2. 检查“本机允许执行 PowerShell”或所选从机的权限提示；远程权限在那台电脑本机设置。
3. 点击「打开终端」，先用 `hostname` 确认命令实际运行在哪台电脑，再执行工作命令。
4. 终端保留当前目录和变量；关闭对应终端会结束这条交互会话。

权限开关默认开启，已有明确关闭的设置会保留。命令使用运行程序的 Windows 账户权限，不会自动提权。关闭权限会结束本机 PowerShell 交互会话；其他硬件工具的权限独立控制。

## 八、USB 继电器（插件）

**安装：** 打开「工具 → 插件管理」，安装 `plugin/` 下的 `usb-relay-*.dmp` 并启用；工具菜单的「本机工具」分组随即出现「USB 继电器…」。

**准备：** 将继电器接到执行电脑。该设备使用 USB HID 接口，Windows 自带驱动；在设备管理器中确认能识别到它即可。继电器 DLL 与辅助程序已随插件包提供，无需另外准备厂商控制程序，也无需指定工具目录。

1. 本机使用：「工具 → USB 继电器…」，目标电脑选“本机”。远程使用先在从机 B 的同一面板把目标选为“本机”，勾选顶部的权限行「允许主控使用本机工具（自动启用插件）」，再在主控的「远程 · B」分组打开该入口。
2. 点「查找设备」，从列表按序列号选择目标，点「打开设备」。这一步是逻辑接入，不改变触点。
3. 点「刷新状态」，确认通道状态；绿色为已接通，红色为已断开，灰色为未知。核对负载后再逐路“打开/关闭”，或“打开所有/关闭所有”。

```text
继电器面板示意
目标电脑 [本机 / 从机 B ▼]  [刷新连接]
[✓] 允许主控使用本机工具（自动启用插件）
[查找设备]  设备 [枚举出的序列号 ▼] [打开设备] [关闭设备]
通道 1 [已接通/已断开/未知]   [打开] [关闭]
[刷新状态]  [打开所有] [关闭所有]
```

| 现象 | 先处理什么 |
|---|---|
| 查找设备为空 | 在执行电脑检查 USB 连接、驱动，以及设备管理器是否识别到继电器 |
| DLL 加载/初始化失败 | 展开「分阶段诊断（只读）」，依次做文件检查、DLL 加载、初始化、枚举；保留失败阶段和错误 |
| 状态为未知/操作超时 | 先刷新状态或在执行电脑核对实物，不能把未知当作断开；不自动重复切换 |

分阶段诊断只执行所选阶段及其前置步骤，不自动切换触点；读取状态阶段需提供设备序列号。**“关闭设备”、关面板或退出程序都不会自动断开触点。** 若确实需要全断开，核对负载后明确执行“关闭所有”。触点状态也不能单独证明下游设备已正常供电。

## 九、DB 固化烧写（插件）

**安装：** 打开「工具 → 插件管理」，安装 `plugin/` 下的 `db-flash-*.dmp` 并启用；工具菜单的「本机工具」分组随即出现「DB 固化烧写…」。

**准备：** 在执行电脑放好完整的厂商固化包和镜像，保留原目录结构；连接板卡并安装对应下载/fastboot 驱动。发布 EXE 内置运行时和 fastboot，不要为普通界面烧写另装项目源码。厂商固化包需用户自备。

```text
D:\DBPackage\                     ← 选择这个固化包根目录
  flashall.bat
  flash_all.sh                    ← legacy 平台需要；p300-udp 没有
  flash_cfg.ini                   ← p300-udp 平台文件
  scripts\
    download_image.py
  …厂商原有的镜像、工具及 USB 库目录（保持原结构）
```

1. 本机使用：「工具 → DB 固化烧写…」，目标电脑选“本机”。远程使用先在从机 B 的同一面板把目标选为“本机”，勾选顶部的权限行「允许主控使用本机工具（自动启用插件）」，再在主控的「远程 · B」分组打开该入口。
2. 选择/浏览执行电脑上的固化包根目录并确认。根目录必须包含 `flashall.bat` 和 `scripts\download_image.py`；legacy 平台还需要 `flash_all.sh`，p300-udp 由 `flash_cfg.ini`/脚本内容自动识别，不需要该文件。不要只选 `scripts` 子目录，也不要只提供一份镜像。远程镜像留在 B，填写 B 的路径，本操作不会传输或复制 A 的镜像。
3. 确认后查看“识别平台”和镜像清单，状态行会给出自动识别结果，例如「已自动识别：p300-udp（9 项）」。legacy 为 7 项；p300-udp 为 9 项，多出 `uboot_env.img`（env 分区）和 `lpddr5_fw.bin`（ddr 分区），system 默认勾选（`flashall.bat` 包含，`flashall_mini`/`copy-and-update` 变体可手动取消）。
4. 可选择 ALL 或逐项勾选；外部镜像可批量加入，在对应条目选择实际文件。候选不唯一时明确选择，不以文件名自动识别代替板型/版本确认。p300-udp 的 `images\boot.itb` 缺失时，按厂商 `copy-and-update.bat` 补齐，或手动选择实际的 boot 镜像。
5. 若只显示「标准 DB 固化包」且提示缺少 `flash_all.sh`，先确认是否选到了 p300-udp 包根目录、`flashall.bat`/`flash_cfg.ini` 是否完整。
6. 核对目标 fastboot 序列号；多设备必须明确选择，留空仅适用于执行端能够确认唯一目标的情况。BootROM 下载阶段仍要求唯一可识别板卡。
7. 核对“烧写前准备、安全芯片镜像、用户数据处理、完成后重启”等选项。p300-udp 的安全芯片默认自动检测（`fastboot getvar is-secure-chip`），检测到安全芯片时自动改用 `.pro.enc`/`preboot_sign.itb`；用户数据默认“格式化”，也可改为烧写 `userdata.img` 或擦除。先点「预览执行计划」，逐项看实际路径和操作，再点「开始烧写」。

| 配置项 | 要核对的内容 |
|---|---|
| 固化包目录 | 当前所选执行电脑能访问的完整原包；目录确认成功不代表驱动和板卡连接已通过 |
| 识别平台 | 由固化包脚本自动判断；p300-udp 的 env/ddr 和安全镜像路径与 legacy 不同，不能混用 |
| 勾选镜像 / 实际文件 | 确认板型、固件版本和每一项所用的真实路径；外部文件保留原路径 |
| ALL | 使用原脚本默认流程：legacy 可能擦除用户数据；p300-udp 烧写 system 并格式化 data、重启 |
| 烧写前准备 / 清除启动设置 | 以预览计划的下载、擦除步骤为准；p300-udp 不显示“清除启动设置” |
| 安全芯片镜像 | p300-udp 默认自动；只有明确板型时才固定为“始终安全”或“始终普通” |
| 用户数据处理 | 明确是格式化、擦除还是烧写指定镜像；需要的数据在开始前自行保存 |
| 完成后重启 | 是否在烧写完成后重启目标；单镜像场景也要逐次核对 |

```text
DB 配置与执行示意
目标电脑 [本机 / 从机 B ▼]  [刷新连接]
[✓] 允许主控使用本机工具（自动启用插件）
固化包 [D:\DBPackage] [确认目录]
镜像清单 [勾选项 | 标准名称 | 实际文件]
执行选项 [准备 / 安全芯片 / 用户数据 / 重启]
          [预览执行计划] → 人工核对 → [开始烧写]
          进度和工具输出             [停止烧写]
```

固化包目录错误时先看缺哪份脚本；缺镜像/候选不唯一时补齐或明确选择；等待 fastboot 超时到执行电脑核对板卡模式、数据线和驱动。原包使用的 USB DLL 保留原结构，缺库时保留具体错误，不用其他版本的 DLL 随意替换。

烧写执行会操作真实设备。观察每一步工具输出、最终状态和错误；“已开始”不等于成功。停止使用本工具的「停止烧写」，并等待实际结果；普通 PowerShell 任务取消不能替代烧写取消。关面板不停止后台任务，已写入数据不会回滚；失联或权限撤销也不自动取消已接纳任务，需要在执行电脑确认进度。

## 十、诊断、日志与缓存清理

- **ADB 诊断：** 点击设备栏「⚕ ADB 诊断」，按需选择设备后开始。报告会给出 ADB、端口、授权和设备状态建议，可复制报告；诊断本身不重启 ADB 或改设备。
- **日志：** 到日志页面刷新查看，排错时保留时间、机器、目标与错误文字。日志位置固定在 EXE 旁 `devmux-data/devmux.log`，升级后旧日志会自动迁移过来。清空失败会显示原因；清空日志会丢失排错资料，先保存需要的内容。
- **闲置缓存：** 在已保存的中转配置中点击「清理闲置缓存」，阅读确认框范围后执行。程序保留活动数据、身份与配置；报告可能是部分完成，按提示再次人工确认续扫。

缓存清理按以下步骤操作：

1. 保持当前中转运行，进入「工具 → 跨机中转配置…」，确认显示的是要清理的共享目录；表单修改尚未保存时先核对并保存。
2. 点击「清理闲置缓存」并阅读确认框。范围覆盖该共享根的各部署，删除可确认闲置的历史流、结束会话与过期请求，精简旧回执/归档的大段输出；活动会话、在途数据、心跳、配置、近期变化文件、未知业务文件和最小去重索引保留。
3. 确认后等待本批结果，查看扫描、删除、精简、保留数量及减少的字节数。清理不会停用中转或关闭正在使用的终端。近期结束文件和无法证明闲置的文件仍可能保留，清理不是把目录清空。
4. 若提示「部分完成」，本批已达到处理预算，可再次点击并人工确认继续扫描。续扫位置只保存在本次程序运行的内存中，重开程序后重新扫描；程序不会自动循环或超时重发。
5. 若提示占用、权限或「未完全清理」，记录具体路径和原因，核对对应程序/共享权限后再处理。显示的空间是已扫描文件的逻辑字节，可能与资源管理器的磁盘占用不同，目录仍较大不代表清理没有执行。

清理不能保证消除所有网络或设备卡顿，不要手工删除共享目录的活动文件。

## 十一、插件：安装、米家与 eBPF

四个官方插件都随包放在发布目录的 `plugin/` 下，文件名是 `插件ID-版本号.dmp`：`usb-relay`（USB 继电器）、`db-flash`（DB 固化烧写）、`mijia`（米家设备）、`ebpf`（Linux eBPF 调试）。继电器与 DB 的用法见第八、九章，本节讲安装流程和另外两个插件。

### 1. 安装、启用与更新

1. 打开「工具 → 插件管理」，顶部「目标电脑」默认是“本机”。
2. 点「＋ 安装插件」，可一次多选 `.dmp`，装完状态行显示成功与失败数量。安装**不会**自动启用。
3. 在插件卡片上点「启用」，工具菜单随即出现入口；「本机工具」分组下是本机已启用的插件。
4. 更新：先结束该插件的活动任务，点「停用」，再安装新包并启用。卸载前先停用；米家凭据等私有数据按需备份。
5. 启用/停用状态在重启后自动恢复，不用每次重设。

### 2. 远程使用插件

插件面板顶部的「目标电脑」决定操作对象。目标选“本机”时，下方出现权限行「允许主控使用本机工具（自动启用插件）」。

1. 先在从机 B 装好并启用该插件，再勾选插件管理里该卡片的「允许主控使用（自动启用）」，或直接在 B 的插件面板勾选权限行。
2. B 允许后，主控 A 的工具菜单出现「远程 · B」分组，从中打开同一插件。未启用或未授权时，入口名后带「· 未启用」「· 未授权」。
3. 主控不能替从机勾选或安装。想在 A 上直接装卸 B 的插件，需先在 B 的插件管理底部勾选「允许已验证主控远程安装和卸载插件」。
4. 米家只支持本机，不提供远程入口。

### 3. 米家设备

安装 `mijia-*.dmp` 并启用后，从工具菜单打开并按界面扫码登录；账户及凭据仅保存在本机私有数据目录。MCP 不提供登录或凭据操作。

### 4. Linux eBPF 调试

安装 `ebpf-*.dmp` 并启用后从工具菜单打开。设备要求 aarch64 Linux、root，并允许 ADB shell/push；功能和权限以插件提示为准。

## 十二、让 Agent 使用软件

Agent 通过 MCP 或 JSON CLI 连接**已运行**的程序，共用界面里同一套设备、终端和中转连接。需要远程设备时，先在界面确认从机连接。

1. 下载同一 Release 的 `DevMux-3.2.2-source.zip` 并解压，安装 `requirements.txt`。
2. 在源码目录确认能连上：`python -B agent_cli.py instances`；再运行 `python -B agent_cli.py tools` 看可用工具。
3. 注册 MCP：命令为 `python`，参数为 `-B` 和源码中 `agent_mcp.py` 的绝对路径；有多个实例时追加 `--instance` 和实际 instanceId。

源码客户端只连已运行的 EXE，不要另起 server.py，也不能只复制单个客户端文件。插件管理用 `plugins_manage`（仅本机，安装后不会自动启用，更新前先停用）；查询目标用 `targets_list`，物理操作结果未知时查询原任务，不盲目重试。

工具表、参数、认证、权限、限额与边界见 [开发者说明](/docs/用户/开发者说明.md)；串口各动作与 XMODEM 回执处理也见该文档第一部分。

## 十三、常见问题

| 现象 | 先这样处理 |
|---|---|
| 程序打不开/空白窗口 | 确认 Windows 版本、WebView2 Runtime、目录写入权限，保留报错和日志 |
| 看不到本机设备 | 检查数据线、驱动、USB 调试和设备授权；运行 ADB 诊断。仅管理远程设备的特殊实例可能禁用了本机枚举 |
| 远端电脑可见但连不上 | 两端确认共享目录可读写、角色正确，主控确认目标；按“通讯验证”原因处理，不能只看心跳 |
| 已连接但没有远端设备 | 到从机确认 ADB 能看到设备，检查共享设备范围及授权 |
| 终端只能看不能输入 | 看是否离线、被从机/GUI/Agent 持有输入权；在持权窗口交还或人工接管后重新接入 |
| 串口乱码或没有回复 | 核对 COM、波特率、校验、编码、换行和接线；检查是否被其他软件占用 |
| 远程工具提示无权限 | 到执行电脑把该工具的目标选为“本机”并勾选权限行；继电器、DB 还要在那里勾「允许主控使用」。PowerShell、串口、继电器、DB 分别设置 |
| 工具菜单里没有继电器/DB | 这两项由插件提供，先到「工具 → 插件管理」安装对应 `.dmp` 并启用，菜单才会出现入口 |
| 远程命令一条都不执行 | 先确认从机安装的是当前版本；两端版本一致仍不执行，再查命令白名单、shell 权限与设备状态 |
| Agent 找不到实例 | 先启动程序，确认同机同 Windows 用户、发现目录相同且可读；多实例明确选择 ID |
| MCP 没有工具/启动即退出 | 确认 Python 绝对路径和 websockets，先运行生成脚本的 tools，再看宿主 MCP 日志 |
| Agent 执行返回成功却看不到结果 | 查询任务最终状态和输出；检查内层工具 success、退出码、分页和目标，界面不展示 Agent 任务列表 |
| 控制/烧写超时 | 保留原任务/请求 ID，查实际状态或到执行电脑核对，不重复发起动作 |
| 缓存清理提示部分完成 | 本批达到预算，按提示再次人工确认续扫；不要删除活动文件或反复自动触发 |

反馈问题时带上：程序版本、主控/从机角色、发生时间、执行电脑、目标设备/COM、操作步骤、完整错误及脱敏日志。不要附认证令牌。

## 十四、数据、配置与升级

运行配置、已安装插件及凭据、日志和任务记录统一存放在 EXE 旁的 `devmux-data/`，不要删除，也不要随公开发布包分发。插件私有数据在 `devmux-data/plugins-*/.data/`。多开实例使用各自的 `relay-instance-N.json`，不要让多个实例显式共用配置。共享中转根下的 `adb-share/relay.json` 是协议清单，不能当作应用配置删除。

升级步骤：退出旧版 → 备份 `devmux-data/` → 在原目录替换 EXE（或整个解压新包并保留原 `devmux-data/`）→ 启动。旧数据会兼容迁移，迁移遇到同名目标时保留新目录内容、旧源保留供恢复；不要同时运行旧版参与迁移。备份或迁机时带上整个 `devmux-data/`，不能只复制单个配对或信任文件。

配置损坏或同一小节保存冲突时会明确拒绝覆盖；修正或重新读取后再保存。旧程序不识别新版写入的配置小节，升级后不能只换回旧 EXE 作为完整回退。

升级或迁移后如遇启动异常：窗口空白先检查 WebView2 Runtime；启动被系统阻止时先核对下载来源及摘要，再按组织策略处理；检查 `devmux-data/` 内日志及 `crash_dump.txt`。插件入口缺失时先查插件安装及 enabled 状态，不能停用时先结束活动任务。
