# 串口说明：窗口、参数与 Agent 接入

本文是串口能力唯一的详细说明：连接参数、输入权、日志、快捷指令、XMODEM 和 serial 扩展接口。第一次打开串口的操作路径见 [使用说明](../../使用说明.md) 第六章，两处不一致时以本文为准。

## 打开与参数

从「窗口 → Serial」进入，目标可选本机或已连接从机；刷新 COM 列表后选择端口。默认参数 921600/8/N/1、无流控。波特率可从常用值下拉，也可在右侧输入 1～12000000 的整数。没有串口时只显示空列表，不会打开任何端口。

打开后默认进入主终端区，与 PowerShell、ADB 终端共用标签、网格/水平和单屏布局；拖动标题栏可移出为独立窗口，↙ 返回并保留会话。手动关闭的窗口不会被后台广播重新打开，需要时用主界面刷新按钮恢复。

同一 COM 参数相同时共用连接，参数不同时必须先关闭原连接。拔插后保持断开提示，手动关闭再重新打开；程序不自动重连、不重发。

远程串口：在从机的 Serial 面板把目标选为“本机”，勾选顶部权限行「允许主控使用本机工具（自动启用插件）」（权限行只在选“本机”时出现）。该权限独立于 PowerShell、继电器和 DB，主控不能替从机开启。权限撤销、解除配对、连接代次更新或节点停止会释放相关远程接入，本机接入保留。

## 发送与显示

文本模式可直接在终端键入或用底部输入框。Enter 发送，Ctrl+Enter 换行；编码可选 UTF-8/GBK/ASCII/Latin-1，末尾换行可选 CR/LF/CRLF/无。本地回显默认关闭，设备自身也回显时不要开启。HEX 模式在底部输入完整字节对（例如 `00 FF 41 0D 0A`），不追加换行；切换显示模式会清屏，但只影响显示，不改变字节游标或设备状态。

GUI 与 Agent 共享输出，输入权独占。GUI 打开、接管或发送时可收回 Agent 输入权；Agent 不能抢 GUI 或另一个 Agent。GUI「交还输入权」后，Agent 需显式申请新代次，此前排队的旧输入仍被拒绝。另一个 GUI 持权时，先到那个窗口交还。关闭窗口只释放自己的接入，最后一个接入关闭时才释放物理 COM。

发送结果暂时未确认时，窗口继续显示收到的输出并暂停新输入，不重发；收到明确回执后恢复。长时间未确认可关闭窗口重开，先确认设备实际状态再决定是否重新输入。

## 快捷指令

点工具栏「快捷指令」展开列表，选择指令集，点「+」新增；右键指令可编辑或删除。指令集可新建、改名、删除，至少保留一个。名称与内容分别保存；文本指令按当前编码和换行发送，HEX 指令按字节对发送且不追加换行，发送前先核对窗口当前格式。

指令保存在程序旁 `devmux-data/commands.json` 的串口小节，与 ADB 指令集共用同一个文件但互不影响；旧版独立文件 `serial-commands.json` 会在首次启动时并入并改名 `.migrated`。本机与远程串口窗口共用这套指令集，保存失败会显示原因。

## XMODEM

点工具栏「XMODEM…」展开传输面板：

1. 确认所选电脑与 COM 正确。参数需为 8 数据位并禁用 XON/XOFF；沿用当前波特率、校验、停止位、硬件流控和 DTR/RTS，程序不修改设备也不执行烧写命令。
2. **发送**：先在设备端进入 XMODEM 接收模式，选择发送包长 128 字节或 1K，再点「发送文件…」选本机文件。128 字节按对端 C/NAK 自动用 CRC16 或 checksum；1K 要求对端请求 CRC。单文件最多 64MiB，原文件不修改。
3. **接收**：先选 CRC16 或 Checksum，点「接收文件」，再让设备进入 XMODEM 发送模式。128 与 1K 包都能接收，界面显示实际接收字节与重试次数。
4. 成功接收后点「保存接收文件」，在 Windows 另存为窗口填新文件名，不覆盖已有文件；取消保存后可再次保存。远程串口的协议和临时文件在从机执行，最终文件保存在操作者本机。
5. 观察准备、等待握手、传输、结束确认和成功/失败。可「取消传输」，运行时向设备发送 CAN；取消不能撤回设备已收到的数据。准备与传输期间普通输入、快捷指令和接管暂停，其他 GUI 或 Agent 也不能抢占。

XMODEM 不携带文件名和精确原始长度：发送尾块以 1A 填充，接收保留填充字节，二进制文件请按已知长度或摘要核对，不能简单删除所有尾部 1A。接收端结束前会短暂等待重复 EOT 并再次确认，设备恢复提示符后的输出保留。

回执未知时点「查询 / 恢复准备」，沿用原 requestId/transferId，不重新启动文件。上传块按 offset 与内容校验；协议层重传与「普通终端输入不重发」是两回事。关闭传输所属窗口、主界面断开、从机撤销串口权限或程序停止会终止传输并回收临时文件；关闭无关的共享接入不影响所属任务。接收结果只保留到下一次传输或所属接入关闭。

原生独立窗口里点选择/保存文件会先返回主窗口，按提示再点一次；快捷指令的列表、编辑和指令集管理都在当前独立窗口内完成。未升级的从机没有 XMODEM 能力，按钮保持禁用。

## Agent 接入

用 `extension_capabilities` 查询所选电脑的 `tool=serial`，取得 `agentActions` 参数 schema；再用 `extension_call` 的 `action` 调用。目标必须是 `computer:local` 或 `computer:<nodeId>`。

| action | 必要参数 | 返回或语义 |
|---|---|---|
| config | 无 | defaults、remoteAllowed、formats、protocols、xmodem=true、xmodemMaxBytes、xmodemChunkBytes |
| ports | 无 | port/description/hwid/manufacturer/serialNumber/opened |
| open | port、requestId | sessionId、config、state、generation、writable、controller；可选串口参数 |
| status | sessionId | 当前输入权、代次、连接状态 |
| read | sessionId；可选 cursor/limit | 无损 base64 data、nextCursor、droppedBytes、hasMore |
| write | sessionId、generation、data | format=text/hex/base64；text 可选 encoding；`interCharDelayMs` 可选 0～20，默认 0；非零时相邻字符/字节间隔指定毫秒，单次最多 2048 字节；按原样发送，不追加换行。Agent 需持有当前输入权 |
| control | sessionId、generation、operation | take/release，GUI 优先 |
| close | sessionId | 释放当前接入，最后接入释放 COM |
| xmodem-start | sessionId、generation、requestId、direction | direction=send/receive，size（发送必填实际大小）、blockSize=128/1024、checksum=crc/checksum；返回 xmodem.transferId，准备阶段独占 |
| xmodem-upload | sessionId、transferId、offset、data | 连续 32KiB 以内 base64 块，重复块内容必须一致 |
| xmodem-run | sessionId、transferId | 上传完整后启动，receive 直接启动；重复调用不重新执行 |
| xmodem-status | sessionId、transferId | 查询原任务；read/status 也带 xmodem 进度 |
| xmodem-download | sessionId、transferId | 仅成功接收可下载，offset/limit（至多 32768），base64 data、nextOffset、eof |
| xmodem-cancel | sessionId、transferId | 取消所属任务，输入恢复后须用最新 generation |

每次 `open` 使用新的 32 位十六进制 requestId，重复同一请求只返回同一接入；改变配置不能复用 requestId。CLI/MCP 薄客户端未指定时会自动生成，直接调用认证 WS 必须自备。打开超时后用原 requestId 与原配置显式查询，不另开接入。write 的响应丢失或部分发送不能判断设备是否收到，禁止自动重发。

例如 `extension_call`：

```json
{"target":"computer:local","tool":"serial","action":"open","arguments":{"port":"COM3","baudrate":921600,"requestId":"0123456789abcdef0123456789abcdef"}}
```

随后用返回的 sessionId、generation 发送：

```json
{"target":"computer:local","tool":"serial","action":"write","arguments":{"sessionId":"返回的ID","generation":"当前代次","format":"hex","data":"00 FF 41 0D 0A"}}
```

读取时逐页使用 nextCursor，不把 base64 当文本，也不假定一次 read 对应一条回复；完整字节 00..FF 经 base64 无损往返。XMODEM 任务同样用 base64 分块，协议只在串口目标端执行；Agent 沿用现有权限和独占限制，不能读取或取消 GUI 发起的任务。

连接最多 8 个、接入最多 64 个，每连接历史最多 1 MiB，裁剪通过 droppedBytes 明确报告。单次写入最多 65536 字节，读取页最多 65536 字节。30 分钟无人读取或操作会回收连接；持续输出不会无限延长租约。
