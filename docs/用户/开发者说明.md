# DevMux 开发者说明（Agent 接入与插件开发）

> 面向 **Agent 接入方**与**插件开发者**。人工使用功能见 [使用说明](/docs/用户/使用说明.md)；本文只写调用契约、参数、权限、限额、SDK 与打包规则，不复述界面操作步骤。
>
> 分工原则（见 /docs/文档索引.md 规则 12）：用户手册是全集，本文是补集。同一个事实只在用户手册写“怎么操作”，在这里写“怎么调用”。

## 第一部分：Agent 与自动化接入

人工操作先读随 Windows ZIP 提供的 [使用说明](/docs/用户/使用说明.md)。使用 MCP 时，下载同一 Release 的 `DevMux-3.2.3-source.zip`，解压后安装 `requirements.txt`，注册其中 `agent_mcp.py` 的绝对路径。源码客户端连接已运行 EXE，不要另启动 server.py；原 agent_cli.py/agent_mcp.py 有项目传递导入，不能单独复制。旧版手工生成脚本仅覆盖旧工具表，新增插件管理使用本版源码入口。

本地 Agent 通过 JSON CLI 或 MCP stdio 连接已运行的 DevMux。两者共用应用的设备列表、ADB shell 和中转连接，不启动第二套 ADB 轮询。电脑 PowerShell 和设备 ADB 权限独立。

### 启动和权限

1. 启动已交付且支持 Agent 的 DevMux；跨机操作时两端均运行支持对应能力的版本。源码运行可用 `python server.py`；接入已运行 EXE 时不要另起后端。
2. 按现有流程配置共享目录，由主控确认从机连接。
3. 在执行电脑的「窗口 → PowerShell…」直接控制「本机允许执行 PowerShell」。新配置及未设置该字段的旧配置默认开启，已有明确关闭的配置保留。修改后自动保存并立即生效，无需启用或重启中转；关闭将结束本机 PowerShell 交互会话。
4. 「窗口 → PowerShell…」选择本机主控或已连接的从机，点击「打开终端」在主终端区域新增对应的 PowerShell 面板和标签，沿用 ADB shell 的配色、字体、网格/单屏布局、最小化/最大化、复制粘贴及可拖拽命令框；可连续输入、保留变量/目录、使用键盘 Ctrl+C；关闭终端面板会停止对应 shell，不再显示 Ctrl+C 按钮。权限开关控制当前电脑；远程电脑权限必须在那台电脑的「PowerShell」中设置。界面不展示命令记录或 Agent 任务，Agent 通过下面的 MCP/CLI 操作接口接入。

PowerShell 按运行 DevMux 的 Windows 账户权限执行，不自动提权。允许通用脚本意味着该账户的常规文件/程序权限；它不是受限工具沙箱。共享目录须由受信任账户写入，既有连接确认不能替代对不可信共享目录写入者的密码学认证。

### CLI

在项目目录运行（Python 3.10+，依赖沿用项目的 websockets）：

```powershell
python -B agent_cli.py instances
python -B agent_cli.py tools
python -B agent_cli.py targets_list
```

存在多个运行实例时，加 `--instance <instances 返回的 instanceId>`。发现信息默认位于 `%LOCALAPPDATA%\ADBManager\runtime\`，按实例分文件。该历史目录名为兼容旧版 Agent 配置而保留。输出不包含令牌。需要覆盖时，两端客户端/应用使用同一个 `ADB_AGENT_RUNTIME_DIR`，目录应限当前用户访问。目录不可写会记录明确错误，桌面后端仍可启动。

为避免 PowerShell 多层引号，参数优先使用 UTF-8 JSON 文件。例如 `request.json`：

```json
{"target":"computer:local","script":"hostname; Get-Location","timeout":30}
```

```powershell
python -B agent_cli.py windows_exec --args-file request.json
```

`windows_exec` 立即返回 jobId，使用 `job_status` / `job_output` 查询；不要用调用返回快慢推断命令完成。远程电脑目标为 `computer:<nodeId>`，设备为 `device:<服务器返回的完整 key>`，均从 `targets_list` 读取。

```json
{"target":"computer:local","jobId":"返回的任务ID"}
```

```powershell
python -B agent_cli.py job_status --args-file request.json
python -B agent_cli.py job_output --args-file request.json
```

`job_output` 可指定 stream=stdout/stderr、cursor 和 limit，使用 nextCursor 继续分页。原始字节为 base64 data，text 去 ANSI；截断/裁剪通过 droppedBytes 报告。

### MCP

注册 stdio 服务器：命令 `python`，参数为 `-B` 和本项目的 `agent_mcp.py` **绝对路径**，多实例时再追加 `--instance` 与实例 ID。不需要额外 MCP SDK。入口示意：

```json
{
  "command": "python",
  "args": ["-B", "D:\\workspace\\ai-work\\DevMux\\agent_mcp.py"]
}
```

MCP 支持 initialize、ping、tools/list、tools/call，stdio 为 UTF-8 逐行 JSON-RPC。协议依据 MCP 2025-03-26，并兼容 2024-11-05；输出不混普通日志。各宿主的注册位置按其配置方式设置，本次不自动修改宿主配置。

| extensions_list | 当前版本注册的扩展、动作与参数说明，新增注册工具自动进入列表 |

### 继电器和 DB 烧写扩展

先调用 `extensions_list`，再通过 `targets_list` 选择完整电脑目标 ID，以 `extension_capabilities` 查询执行端是否支持该扩展和是否允许。本版注册 `serial`（串口）、`relay`（继电器）及 `db-flash`（DB烧写）；列表描述的是本版工具，旧从机可能尚未支持，须实际查询。能力结果的 `agentActions` 含各动作参数 schema，`allowed` 表示该目标是否允许调用。

```powershell
python -B agent_cli.py extensions_list
python -B agent_cli.py extension_capabilities --args-file request.json
python -B agent_cli.py extension_call --args-file request.json
```

能力查询的 `request.json`：

```json
{"target":"computer:从机nodeId","tool":"relay"}
```

继电器支持 config、save、scan、open、close、status、set、diagnose。使用执行电脑的 toolDir 保存目录，scan 后按返回 serial 打开设备；set 的 operation 为 open/close，channel 为实际通道号，255 表示全部通道。逻辑 close 保持触点不变，控制结果不确定时读取 status，不自动重发控制动作。例如：

```json
{"target":"computer:从机nodeId","tool":"relay","action":"set","arguments":{"channel":1,"operation":"open"}}
```

DB 支持 config、save、browse、catalog、plan、start、status、cancel。目录、镜像和浏览路径属于执行电脑，browse 不传输文件。先 catalog/plan 核对固定计划，再 start；开始返回任务标识不代表烧写完成，使用 status 查询实际状态及日志。例如：

```json
{"target":"computer:从机nodeId","tool":"db-flash","action":"start","arguments":{"toolDir":"D:\\firmware\\DB","selected":["system"],"options":{"prepare":false},"requestId":"0123456789abcdef0123456789abcdef"}}
```

CLI/MCP 在未提供 start.requestId 时会在发请求之前生成32位十六进制标识；明确提供的标识不会被替换。直接调用认证 WS 必须提供它。正常响应在外层 data.requestId 返回；响应丢失时失败结果的 data.requestId 仍可查询。重复开始须复用原标识，不能生成新标识盲目重烧。查询参数如下，after 为事件游标、每页最多32事件：

```json
{"target":"computer:从机nodeId","tool":"db-flash","action":"status","arguments":{"requestId":"0123456789abcdef0123456789abcdef","after":0}}
```

cancel 使用 jobId 或 requestId，沿用 DB 任务停止策略；撤回未确认的 requestId 会阻止迟到开始。请求成功不等于任务已停止，继续查询实际状态。开始和状态结果不确定时通过 operationUncertain 标识，不自动重试。

扩展权限独立于 PowerShell。permission 仅能以 computer:local 在执行电脑本机设置 arguments.allowed；主控不能替从机开启权限。远程 DB 禁止自定义 pythonPath/fastbootPath，任务沿用已验证主控 nodeId 归属；其他主控不能停止它。既有配对、撤销、连接代次、锁内授权及 DB 防重烧均由执行端执行，Agent 不绕过这些检查。

### 持续交互

对电脑 `session_open` 创建 PowerShell PTY，同一会话保留变量/cwd；对设备则接入已有终端，不再创建第二个设备 shell。session_write 原样发送字符串，回车建议 `\r`，Ctrl+C 为 `\u0003`。read 用字节游标读取合并输出，不提供通用命令退出码，输出静默不代表命令完成。

PowerShell 会话不加载 profile，不修改 ExecutionPolicy；使用对应版本的标准用户/系统/安装模块目录，避免宿主注入另一版本 PSReadLine。自定义模块可按完整路径 Import-Module。

设备会话期间 GUI 只读，可用「接管」使旧 Agent 接入失效。从机本地接管沿用原有中转控制权；连接/会话代次变化后必须重新接入。设备 session_close 只释放 Agent 输入权，不关闭原设备 shell。电脑 session_close 则关闭创建的 PowerShell。

Agent 会话 ID 由常驻实例持有，可跨 CLI 调用；应用重启后失效，不自动重放输入。关闭不再使用的会话，避免占满上限。

### 文件传输

设备目标：push 的 paths 为主控本机来源，destination 为设备路径；pull 的 paths 为设备路径，destination 为主控保存路径。沿用从机 push/pull 白名单。

电脑目标：PowerShell 权限启用后可传输，远端路径是 `target_status.filesRoot` 内的**相对路径**，不允许绝对路径、上级路径或链接。push 的 destination 是暂存子目录；pull 的 paths 是暂存内文件/目录。主控本机路径可为绝对路径。

```json
{"target":"computer:从机nodeId","direction":"push","paths":["D:\\firmware\\image.bin"],"destination":"firmware"}
```

上传后在从机用 `filesRoot\firmware\image.bin` 调用工具。包限制沿用现有 10 GiB/100000 项；包校验成功不等于固化成功。传输超时保留可能仍在读取的包，不支持断点/取消。目标落盘失败可能部分完成，不承诺事务回滚。

### 任务恢复和限制

任务持久记录在配置旁 `windows-jobs-*`，包含所有者、状态、账户、脚本哈希及输出文件。重启时原运行任务标为 interrupted，不自动重跑；已完成日志通过接口读取，界面不展示 Agent 任务。

同一调用者重复 jobId 返回原任务；连接超时返回结果未知，应查询原 jobId/jobs_list，不能盲目重新启动。CLI 自动生成 jobId，也允许调用者提供固定的 32 位小写十六进制 ID。

单次任务最多 8 个并行、每路输出最多 32 MiB、历史最多 512 条；满额时明确拒绝新任务，停用执行服务后可归档任务目录。交互最多 8 个会话，有界历史 1 MiB；设备 Agent 接入历史 128 KiB，裁剪明确报告。单次任务默认 30 秒，最长 86400 秒；交互会话不使用命令超时，连续 30 分钟无读取/输入后释放。终端窗口打开时持续读取，不受该闲置限制。

普通 PowerShell 任务取消、超时、应用退出通过 Windows Job Object 回收子进程树。DB 烧写使用独立扩展的 start/status/cancel 和任务策略，不使用普通 job_cancel；不能将任务开始、停止请求或工具进程返回视为设备固化验收完成。

### 验收边界

`python -B tests/test_agent.py` 覆盖真实 PowerShell/PTY/子进程、双节点中转/权限/去重、电脑文件、认证接口、CLI 和 MCP；`tests/test_agent_ui.py` 保留原有 Edge 回归并增加 PowerShell 终端交互、Ctrl+C 和权限入口实测。运行全套 `python -B tests/run_all.py`。

`python -B -m tests.test_agent_extensions` 覆盖实际认证 WS/MCP/CLI、模拟继电器、模拟 DB 任务、本机/真实中转选路、执行端权限、身份、防重烧、取消、丢失回执追踪及后续注册工具发现。扩展通过模拟执行器验证，不操作实体继电器或板卡。

同机双节点验证不能替代真实双机 SMB、真实 ADB 设备、继电器和固化现场验收；未开展的硬件项不能标记通过。

协议参考：[MCP stdio](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports)、[MCP tools](https://modelcontextprotocol.io/specification/2025-03-26/server/tools)。

### 远程交互响应

双端更新后，PowerShell 的创建和关闭走控制队列，持续输入、输出和尺寸调整使用固定的追加流文件，不再逐次等待共享目录请求与回执。输入返回 queued 表示已经送入流，命令结果以实际回显为准。从机持续检查权限、主控身份、在线状态及连接代次；权限关闭、解除或节点停止时关闭旧流。20 秒读取保活和 30 分钟闲置释放保持无人使用时的回收。旧从机没有协商持续流时自动沿用原控制协议。页面输入后以 10 毫秒间隔观察输出，闲置时降频。SMB 或同步盘自身延迟仍会影响字符流；日志中的延迟来自同机双实例，不能替代真实双电脑共享目录的测量。


### Serial 串口接入

用 `extension_capabilities` 查询所选电脑的 `tool=serial`，取得 `agentActions` 参数 schema；再用 `extension_call` 的 `action` 调用。目标必须是 `computer:local` 或 `computer:<nodeId>`。

| action | 必要参数 | 返回或语义 |
|---|---|---|
| config | 无 | defaults、remoteAllowed、formats、protocols、xmodem=true、xmodemMaxBytes、xmodemChunkBytes |
| ports | 无 | port/description/hwid/manufacturer/serialNumber/opened |
| open | port、requestId | sessionId、config、state、generation、writable、controller；可选串口参数 |
| status | sessionId | 当前输入权、代次、连接状态 |
| read | sessionId；可选 cursor/limit | 无损 base64 data、nextCursor、droppedBytes、hasMore |
| write | sessionId、generation、data | format=text/hex/base64；text 可选 encoding；`interCharDelayMs` 可选 0～20，默认 0；非零时相邻字符/字节间隔指定毫秒，单次最多 2048 字节；按原样发送，不追加换行。Agent 需持有当前输入权 |
| control | sessionId、generation、operation | take/release，GUI 优先 |
| close | sessionId | 释放当前接入，最后接入释放 COM |
| xmodem-start | sessionId、generation、requestId、direction | direction=send/receive，size（发送必填实际大小）、blockSize=128/1024、checksum=crc/checksum；返回 xmodem.transferId，准备阶段独占 |
| xmodem-upload | sessionId、transferId、offset、data | 连续 32KiB 以内 base64 块，重复块内容必须一致 |
| xmodem-run | sessionId、transferId | 上传完整后启动，receive 直接启动；重复调用不重新执行 |
| xmodem-status | sessionId、transferId | 查询原任务；read/status 也带 xmodem 进度 |
| xmodem-download | sessionId、transferId | 仅成功接收可下载，offset/limit（至多 32768），base64 data、nextOffset、eof |
| xmodem-cancel | sessionId、transferId | 取消所属任务，输入恢复后须用最新 generation |

每次 `open` 使用新的 32 位十六进制 requestId，重复同一请求只返回同一接入；改变配置不能复用 requestId。CLI/MCP 薄客户端未指定时会自动生成，直接调用认证 WS 必须自备。打开超时后用原 requestId 与原配置显式查询，不另开接入。write 的响应丢失或部分发送不能判断设备是否收到，禁止自动重发。

例如 `extension_call`：

```json
{"target":"computer:local","tool":"serial","action":"open","arguments":{"port":"COM3","baudrate":921600,"requestId":"0123456789abcdef0123456789abcdef"}}
```

随后用返回的 sessionId、generation 发送：

```json
{"target":"computer:local","tool":"serial","action":"write","arguments":{"sessionId":"返回的ID","generation":"当前代次","format":"hex","data":"00 FF 41 0D 0A"}}
```

读取时逐页使用 nextCursor，不把 base64 当文本，也不假定一次 read 对应一条回复；完整字节 00..FF 经 base64 无损往返。XMODEM 任务同样用 base64 分块，协议只在串口目标端执行；Agent 沿用现有权限和独占限制，不能读取或取消 GUI 发起的任务。

连接最多 8 个、接入最多 64 个，每连接历史最多 1 MiB，裁剪通过 droppedBytes 明确报告。单次写入最多 65536 字节，读取页最多 65536 字节。30 分钟无人读取或操作会回收连接；持续输出不会无限延长租约。

### 本机插件管理（3.1.4 版本引入，3.2.0 沿用）

MCP/CLI 工具 `plugins_manage` 复用认证 Agent 连接和插件管理器。无需开启 PowerShell 权限。只支持本机，不接受 target，不修改远程授权策略。远程扩展发现与调用继续走既有已验证连接及执行端权限；本工具不提供远程安装或启停。

参数按动作严格校验：list 仅含 action；install 含 action、package（完整 .dmp 的 base64，大小受现有管理器限制）；enable/disable/uninstall 含 action、id。install 同时用于更新：先 disable，再 install 新包，最后 enable。停用存在活动任务的插件会失败；启用中的插件不能直接更新或卸载。未知字段、无效包、未安装 ID 和生命周期错误通过 MCP isError 返回。

```json
{"action":"list"}
```
```json
{"action":"enable","id":"example"}
```
```json
{"action":"disable","id":"example"}
```

生成安装参数文件（不要把 base64 手工粘贴到命令行）：

```powershell
@{action='install'; package=[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path '.\plugin\usb-relay-1.0.0.dmp')))} | ConvertTo-Json | Set-Content -Encoding utf8 request.json
python -B agent_cli.py plugins_manage --args-file request.json
```

成功结果的 data 包含 target、action、result 和操作后的 plugins 清单（id/version/enabled）。确认安装版本和启停状态；结果未知时先 list，不能盲目重装。连接令牌沿用当前用户受限的实例发现目录，不在公开输出和发布包中分发。

## 第二部分：插件开发

### 五分钟开始

在 DevMux 仓库根目录使用项目 Python 环境，无需安装额外前端框架：

```powershell
python plugin_dev.py create plugins/my-tool --id my-tool --name "我的工具"
python plugin_dev.py check plugins/my-tool
python plugin_dev.py serve plugins/my-tool
python plugin_dev.py pack plugins/my-tool dist/my-tool.dmp
```

`serve` 输出包含随机访问令牌的本机 URL，复制到浏览器即可调试。修改前端源码后点击“刷新界面”；修改 Python 后点击“重新加载后端”。这会重新校验源码、重建临时包并重启调试进程；有活动任务时 `can_stop()` 可阻止重载。配置和日志写到临时环境，不读取应用里已安装插件的数据，退出后清理。开发预览不会模拟远程连接或原生文件选择器，这两类能力须在实际应用中验证。本机工具上下文和后端调用可直接调试；调试仍会执行真实业务代码，设备操作由开发者自行选择。

生成的工程包含 `manifest.json`、`main.py`、`index.html`、`app.js`、README 和供 AI 开发遵循的 AGENTS.md。参考 `plugins/example` 可运行示例，三个官方插件也使用同一套公开 SDK。

`pack` 只是生成开发包，装进运行实例才能用：打开「工具 → 插件管理」→「＋ 安装插件」选择 `.dmp` → 在插件卡片上点「启用」，工具菜单才出现入口。完整安装/启用/更新流程见 [使用说明](/docs/用户/使用说明.md) 第十一章。

自建插件的 `pack` 默认输出到 `dist/my-tool.dmp`（`dist/` 根）；官方随包插件由 `release_plugins.py` 生成到 `dist/plugin/插件ID-版本号.dmp`。`dist/` 由构建流程自动同步白名单内容，手工放入 `dist/` 根目录的 `.dmp` 不属于交付产物，仅用于本地调试安装。

### 前端 SDK 与界面

源页面引用公共资源和插件内资源，打包器会自动内联为单个页面：

```html
<link rel="stylesheet" href="devmux:ui.css">
<script src="devmux:sdk.js"></script>
<script src="app.js"></script>
```

打包不支持外部脚本、外部样式、CSS `@import`、外部媒体和越界路径。图片使用 data URL；复杂前端可先用自己的构建工具输出普通脚本，再交给插件打包器。`check` 校验清单、工厂函数、Python 语法和前端引用，不执行插件后端。

```javascript
const {ui, call} = DevMuxPlugin;
const page = ui.mount({title:'我的工具', description:'示例功能'});
const form = ui.form([{name:'text', label:'内容', type:'text', required:true}]);
const output = ui.log({limit:100});
page.body.append(form, ui.button('执行', async () => {
  if (!form.reportValidity()) return;
  const result = await call('echo', form.values());
  output.appendLine(result.text);
}, {variant:'primary'}), output);
```

| 接口 | 用途 |
|---|---|
| `call(action, arguments, {timeout})` | 调用自己的后端，返回业务数据；失败抛出 `PluginError` |
| `hostCall(type, payload, {timeout})` | 调用 `pick-file`、`pick-directory` 或自己的 `extension-tool` |
| `request(type, payload, timeout)` | 保留原始结果结构的底层适配；type 为 `plugin` 或上述宿主接口 |
| `context` | 只读的窗口初始 `{target, remote}`，远程窗口由宿主锁定目标 |
| `RemoteContext(container, tool, onChange, name)` | 公共目标栏、连接状态与执行端权限提示；使用 `new` 创建 |
| `close()` | 请求关闭当前独立窗口，释放本页资源，不停止插件后端 |
| `listen(element, event, callback, options)` | 注册随页面释放的监听，返回取消函数 |
| `interval(callback, milliseconds)` | 注册随页面释放的定时器，返回定时器 ID |
| `onDispose(callback)` / `dispose()` | 注册清理 / 幂等释放，回调按注册逆序执行 |

`call` 和 `hostCall` 对 `{success:true,data:...}` 返回 `data`，普通业务对象原样返回；`success:false` 抛错。`request` 始终保留结果结构，超时等通信失败返回 `{success:false, output, code}`。请求 ID、响应来源检查、超时和待处理请求释放由 SDK 管理。超时结果未确认，不自动重试硬件操作。

| 公共 UI 接口 | 返回与行为 |
|---|---|
| `ui.mount({title,description,content})` | 标准页面骨架，返回 `body`、`message`、`element` 等；每个工具使用一个主页面 |
| `ui.button(label, callback, {variant,disabled})` | 自动处理执行中禁用及错误提示的按钮 |
| `ui.form(schema, values)` | 表单 DOM；支持 text/password/number/boolean/select，`values()` 读取，`control(name)` 获取控件 |
| `ui.status(text, kind)` | 状态 DOM，`update(text,kind)` 更新；kind 为 info/success/warning/error |
| `ui.table(columns, rows)` | 安全文本表格；列为 `{key,label}`，`update(rows)` 更新 |
| `ui.log({limit})` | 限定行数的日志 DOM；`appendLine(text)` 和 `clear()` |
| `ui.dialog({title,content})` | 标准模态框；`show()`、`hide()`、`destroy()` |
| `ui.registerView(name,factory)` / `renderView(name,container,props)` | 注册和渲染插件内自定义视图；卸载页面时自动撤销注册 |

自定义业务布局可以使用普通 DOM，但按钮、表单、表格等通用外观应复用 SDK。主题集中在 `plugin_sdk/ui.css`，通过 `--bg-dark`、`--bg-panel`、`--text`、`--text-dim`、`--border`、`--accent`、`--error` 等变量扩展。不要复制主程序 CSS，也不要为主页面创建浮动窗口。宿主负责工具菜单注册、插件管理卡片和原生独立窗口，内部业务切页可使用视图注册接口。

### 后端资源与权限

```python
from plugin_sdk import Plugin

class Tool(Plugin):
    def __init__(self, root):
        super().__init__(root)
        # self.data_dir: 当前插件的独立持久数据目录
        # self.on_dispose(resource.close): 注册资源清理

    def call(self, action, arguments):
        if action == 'echo':
            self.logger.info('Echo invoked')
            return {'text': arguments.get('text', '')}
        raise ValueError('未知动作')

def create_plugin(root):
    return Tool(root)
```

继承 SDK 基类是可选的，原有工厂与调用契约仍有效。SDK 清理按逆序执行，一个回调失败不阻止其余清理；关闭过程幂等。日志和标准错误输出保存到 `.data/<插件ID>/runtime.log`；开发预览可直接点击“查看日志”。主程序的本机管理接口 `logs` 返回最多 64 KiB 日志文本；不通过远程目录接口暴露日志。

新插件在 `permissions` 中显式声明需要的 `pick-file`、`pick-directory`；未声明时宿主拒绝相应接口。三个官方插件已显式声明，旧包没有该字段时保留原有文件选择兼容行为。`extension-tool` 始终限制为自身工具，远程窗口只能操作原从机。需要远程能力的插件还须声明 `tool`、`actions`，实现执行端权限与 `__owned__` 任务所有者校验；仅声明清单不会自动获得远程授权。

### MCP / Agent 访问

MCP 继续使用统一入口 `extensions_list`、`extension_capabilities` 和 `extension_call`，与界面共享同一个插件进程及数据目录，无需再启动一套设备服务。

- 清单 `actions` 声明可供本机及经授权从机调用的动作；`localActions` 声明仅供执行端本机 MCP/Agent 调用的动作。可以同时声明，但 `localActions` 不会赋予远程能力。
- 插件启用时注册，停用或卸载后撤销。`extensions_list({})` 仅返回本机已启用的服务，不会虚报未安装的插件。
- `extensions_list({"target":"computer:<从机nodeId>"})` 经已验证的连接查询从机已安装的远程插件，包含启用和授权状态；主机无需安装同一插件。停用插件仍显示已安装状态，调用前须在从机启用并授权。
- `extension_capabilities` 和 `extension_call` 使用明确的 `target`、`tool`，远程调用保留连接验证、执行端授权和任务所有者校验；不会回退到本机。
- 米家声明 `localActions: ["status", "snapshot", "read-switch", "set-switch"]`，须先在本机界面登录。MCP 不开放登录、退出登录或凭据操作，也不能通过远程目标控制米家。

例如调用本机米家登录状态：`extension_call({"target":"computer:local","tool":"mijia","action":"status","arguments":{}})`。新插件无须修改 MCP 工具列表；声明动作并实现后端校验后即可动态发现。

### 打包与运行约定

在 `plugins/example` 基础上开发，使用：

```powershell
python plugin_pack.py plugins/example dist/example.dmp
```

在工具 → 插件管理中选择 `.dmp` 文件安装，然后启用、打开。无需重启。更新和卸载前先停用；插件停止后，其窗口一起关闭。

清单声明 `id`、`name`、`version`、`apiVersion: 1`、`backend`（Python 文件）及可选的 `frontend`（HTML 文件）。ID 是稳定的小写字母、数字和连字符标识。

后端导出 `create_plugin(root)`，返回提供 `call(action, arguments)` 和可选 `close()` 的对象。每个插件在独立进程内串行处理调用。结果必须可 JSON 序列化；异常返回错误。普通 print 输出转到诊断流，不能自行写入协议标准输出。冻结版插件可使用主程序已打包的 Python 模块；新增第三方依赖须先验证打包兼容性。

前端为自包含 HTML（样式、脚本内联），在可移出主程序边界的独立桌面窗口中加载。通过 `parent.postMessage({type:'devmux-plugin-call', id, action, arguments}, '*')` 调用自己的后端。父页面返回 `{type:'devmux-plugin-result', id, result, error}`。使用唯一请求 ID，并检查消息来源是 parent。页面在 sandbox iframe 中运行。

当前包通过本地文件分发，仅安装项目发布的可信包。安装成功不表示已启用；启动失败会显示错误。调用超时会结束插件进程，返回结果未确认，不自动重试。插件需要自行管理物理操作的幂等性；尚不支持在任务执行中安全强制停用，开发硬件插件前须补齐任务准入和停止协议。

继电器、DB 和米家现在均由插件包提供，基础安装包不再创建它们的内置服务。串口和跨机中转保持核心能力。本机有前端入口的已启用插件显示在工具菜单的“本机工具”分组中；已停用插件可从插件管理启用或打开。继电器和 DB 启用时注册到现有远程与 Agent 扩展接口，权限仍由执行端插件裁决；米家仅允许本机使用。

插件管理选择的电脑只影响管理对象。工具菜单另外按从机分组展示其已安装、具有前端且支持远程操作的插件；未启用或未授权保留状态提示。本机米家等入口不会随管理对象切换而消失。打开工具菜单时刷新发现状态。

从机独有的插件无需再安装到主机。开启“允许主控使用”后，主机通过已验证连接分块获取自包含 HTML，校验接口版本、大小和 SHA256，将页面缓存在插件目录的 `.frontend-cache` 中；不下载后端，不安装或启用本机插件。每次打开先向从机重新校验状态和页面摘要，连接失败、卸载、停用或撤销授权时不能使用旧缓存打开。远程窗口按“电脑 + 插件”独立管理，标题标注机器名，界面请求固定在原从机；本机与多台从机可同时打开同一插件。

清单可以声明 `window.width`、`window.height` 以及 `description`。`tool` 和 `actions` 用于声明远程/Agent 接口；对应插件须实现 config、permission 和 __owned__ 动作。插件存在后台任务时应实现 can_stop() 并返回 False，底座将拒绝停用。清单 `timeout` 可将本地调用上限配置为 1–180 秒。

清单可选声明 `minAppVersion`（如 `"3.2.0"`）。只有插件真用到新版宿主能力时才需要填，底座据此决定是否提供自动升级：当前主程序低于该值时，插件不会出现在可升级列表里，界面提示先升级主程序。这避免了“插件升上去了、宿主太旧、一启用就报错”的组合，也让插件在多数情况下能脱离主程序版本独立发布。

插件 HTML 只应提供工具内容，不要再创建自己的浮动窗口外壳、拖动标题栏或缩放边框。系统窗口由底座统一管理，关闭视图不会停用插件或结束后台任务。浏览器运行时使用独立弹出页面，需要允许弹出窗口。


### 官方插件发布规范

执行 `python release_plugins.py dist`，将全部官方插件（USB 继电器、DB、米家、eBPF）生成到 `dist/plugin/插件ID-版本号.dmp`。正式与调试构建均自动调用此步骤。插件启停选择会持久化并在应用重启时恢复；插件数据与运行日志位于 EXE 旁 `devmux-data/plugins-*/.data/`，发布包不得包含运行数据。

官方插件可以脱离主程序单独升级：客户端只认 `plugin_catalog.OFFICIAL_PLUGINS` 里的四个 ID，按发布清单 `latest.json` 的 `plugins` 段比较版本，从 release 下载对应的 `.dmp`，校验 SHA-256 后自动停用、替换、重新启用；替换前的版本备份在 `devmux-data/plugins-*/.backups/插件ID/版本号/`，失败会退回。因此**改动官方插件内容必须递增该插件 `manifest.json` 的 `version`**，否则发布后不会被识别为新版本；只改主程序、不动插件时也不要顺手改插件版本，客户端不会因此打扰用户。
